# ROM 용량 정책

특성의 16비트 종류/강화 등급과 별도 배정표는 유지한다.
카트리지 용량 확대는 RAM, 8비트 특성 슬롯, 11비트 종 저장 한계를 확대하지 않는다.

`rom_capacity.py`와 `patch_engine.apply_module._serialize_rom`을 연결했다.
mega_evolve 적용 결과와 이후 모듈(한글 포함)을 저장할 때 다음 규칙을 사용한다.

- 128MiB 이하는 기존 128MiB 카드 용량을 유지한다.
- 실제 직렬화 크기가128MiB를 넘으면256MiB,256MiB를 넘으면512MiB로 올린다.
- 이후 파일이 작아져도 이미 선택한 용량을 다시 줄이지 않는다.
- 데이터 파일을 256MiB까지 패딩하지 않는다. 기존처럼 trimmed ROM을 출력한다.
- ndspy로 파일 배치, FAT/FNT, 사용 크기 필드를 재생성한다.
  카드 용량 필드를 바꾼 경우 헤더 CRC도 갱신한다.
- 512MiB를 초과하면 잘못된 헤더로 저장하지 않고 오류로 중단한다.
- mega_evolve 이전/미사용 모듈은 기존 저장 경로를 유지한다.
  페이즈 0의 입력 바이트 그대로 복사하는 경로도 유지한다.

확인 시점의 영문 풀스택은 131,253,536바이트(약 125.17MiB),
128MiB 카드 용량까지 2,964,192바이트(약 2.83MiB)의 여유가 있다.
546개의 현재 일반형 배정 프로필은 3,276바이트다.
페이즈5의586개 이미지 패키지와 MD 크기 정보는254,505,232바이트를 추가한다.
실제 공개 apply/verify를 거친 메모리 직렬화는385,989,248바이트(약368.11MiB)다.
따라서512MiB를 선택한다. NDS 파일로 출력하거나 풀스택을 재빌드하지 않았다.

검증 명령:

```powershell
.venv\Scripts\python.exe -B -X utf8 true_patches\mega_evolve\verify_rom_capacity.py
```

정확한128/256/512MiB 경계, 초과 거부, 확장/축소 방지, 헤더 CRC와 사용 크기,
실제 기존 ROM에 4MiB를 메모리에서 추가한 FAT/FNT/파일/오버레이 왕복을 확인한다.
원본 파일 해시는 유지되며 NDS/세이브 파일은 출력하지 않는다.
풀스택 재빌드 및 에뮬레이터 플레이 검증은 수행하지 않았다.

128/256MiB 정책은version4,512MiB 선택은version8, 누락 이미지/신규 진화체 포함 직렬화 검증은version9에 반영했다.
