# 페이즈 1 — 스피드 랭크와 날씨 기반

`mega_evolve` v2 / `phase: 1`.
새 런타임은 적용 시 ov36의 빈 공간을 할당한다. 기존 모듈 예약과 원본
분기·포인터 참조를 확인하고 team_push 및 동굴 체인 앞쪽 구간을 사용하지 않는다.
특성·형태 배정이나 메가진화 메뉴는 아직 적용하지 않는다.

## 스피드

- 저장단계 중립 10, 최소 4, 최대 16. 현재 층의 몬스터 인스턴스별로 관리한다.
- 계산단계는 저장단계와 조건부 보정을 합쳐 4..16으로 제한한다.
- 중립 대비 단계 차이를 d라 하면 d≥0에서 (2+d)/2, d<0에서 2/(2-d)를 적용한다.
  버림 계산하고 실제 계산값은 1..32767로 제한한다.
- 기존 CalcStat의 스피드와 도핑 계산 결과에 배율을 적용하며 명중 계산의
  공격자/방어자 양쪽 스피드 소비자를 연결했다.
- 저장단계 변경과 계산 보정은 이동 배속의 0x110 필드 및 기존 증가/감소
  카운터를 바꾸지 않는다. 층 변경, 몬스터 재초기화, 능력 변화 초기화에서 초기화한다.
- 기존 단순, 클리어바디, 천진의 스피드 처리 기반을 제공한다.
  향후 강화/3특성 엔진은 해당 등급·동료/자기 저하 방지 플래그를 공급한다.
- `balance_change`의 질풍날개 계산 보정 +2가 기존 이동 배속 함수에 들어가
  있던 경로를 제거하고 실제 스피드 계산에 옮겼다. 기존 full-HP 조건은 유지한다.

공개 서비스는 `ME_GetStoredSpeed`, `ME_SetStoredSpeed`, `ME_ChangeSpeed`,
`ME_GetSpeed`, `ME_ResetSpeed`다. 현재 이동속도 기술을 모두 숫자 스피드로
바꾸지 않는다. 배정 특성의 스피드 이벤트 연결은 이후 특성 구현 단계에서 한다.

## 날씨

기존 날씨 ID를 특성·기술 판정에 유지하고, 날씨 강도와 발생원을 별도로 관리한다.
기존 싸라기눈 ID 5와 눈 ID 7은 체감 날씨 조회에서 설경 계열 5로 통일한다.
따라서 아이스바디·눈숨기·눈보라 등 기존 날씨 판정은 새 설경에도 연결된다.
싸라기눈의 주기 피해 경로는 제거하고 모래바람 피해 경로는 유지한다.

| 날씨 | 계산 보정 |
|---|---|
| 쾌청 | 불꽃 기술 위력 ×1.2 |
| 비 | 물 기술 위력 ×1.2 |
| 모래바람 | 바위·땅·강철의 방어/특방 ×1.2 |
| 설경 | 얼음의 방어/특방 ×1.2 |
| 큰가뭄/강한 쾌청 | 불꽃 기술 위력 ×1.5, 기존 큰가뭄 기능 유지 |
| 폭우/강한 비 | 물 기술 위력 ×1.5, 기존 폭우 기능 유지 |
| 강한 모래바람 | 해당 방어/특방 ×1.5, 나머지는 모래바람과 동일 |
| 강한 설경 | 해당 방어/특방 ×1.5, 나머지는 설경과 동일 |

방어 보정은 기존 `BaseStats_FromMonster` 계산 경로에 연결하며 물리·특수
양쪽에 적용한다. 공격 능력치에는 적용하지 않는다. 복합 타입 보정은 한 번만
적용한다. 이전 바위 특방 +2단계와 얼음 방어 +2단계 경로를 제거하여 중첩을 막는다.
변경된 방어/특방은 계산값이며 도핑·종족값·영구 저장 수치를 덮어쓰지 않는다.

날씨 위력 배율은 실제 fx64 형식(하위 32비트 + 상위 Q16 워드)으로 제공한다.
강화 배율은 일반 배율을 대체한다. 반대 타입의 기존 약화와 다른 피해 보정은 유지한다.

최대 20개체 × 3개의 날씨 발생원을 기록한다. 최근 유효한 강한 날씨가 우선하며
모래바람·설경의 강화 상태도 일반 날씨 변경을 막는다. 다른 강한 날씨는 교체 가능하다.
발생원이 죽거나 층에서 사라지거나 특성이 억제되면 이전 유효 발생원을 선택한다.
억제가 해제되면 기존 발생 순서를 유지하여 다시 유효해진다.
기존 원시 날씨의 Alpha 플래그 1/2/3을 유지하고 강한 모래바람/설경을 4/5로 확장했다.
기존 불꽃/물 피해 무효와 강풍 효과는 그대로 연결된다.

`ME_SetWeatherSource`, `ME_ClearWeatherSource`, `ME_ForcedWeather`는
후속 특성 엔진이 사용할 서비스다. 현재 ID 252/253/254는 기존 원시 특성과
연결하고, 모래날림Ⅱ·눈퍼뜨리기Ⅱ 등 강화 특성의 배정/등급 판정은 페이즈 7에서 연결한다.
현재 서비스는 안전하게 기존 ROM 특성 ID 0..254만 허용한다. 다음 특성 엔진이
확장 ID 조회를 제공할 때 16비트 발생원 필드의 조회 경로도 함께 확장한다.

## 문자열과 한글

새 메시지 인덱스는 19750..19752이고 실제 메시지 ID는 인덱스+1이다.
기존 날씨 설명은 의도적으로 새 규칙에 맞춰 수정하고 새 문장은 빈 슬롯에만 넣는다.
영어·한국어 문장 쌍은 이 모듈의 `data/phase1_strings.json`이 소유한다.
한글 엔진은 설치된 영어 문장이 정확히 일치할 때만 이 쌍을 추가 적용한다.
이전 풀스택의 다른 문장에 새 번역을 붙이지 않으며 기존 한글 데이터는 수정하지 않는다.
강한 모래바람·설경이 이전 Alpha의 미사용 메시지를 출력하던 경로도 교체했다.

## 저장 경계

버전 1의 1024바이트 상태 코덱 `ME_ExportState` / `ME_ImportState`를 제공한다.
종·현재 층·동료/적 슬롯에 대응하고 원시 포인터를 저장하지 않는다.
전체 체크섬과 단계·날씨·특성 ID 범위를 검증한 뒤 복원하여 잘못된 자료는 거부한다.

**자동 일반 저장/던전 중간 저장에 이 컴포넌트를 연결하는 코덱 변경은 페이즈 4다.**
지금은 특성 이벤트의 새 저장 랭크 배정 전 기반 단계이며 상태 코덱 자체를 ARM에서
검증한 것이다. 실제 게임에서 새 스피드 랭크나 강화 날씨를 저장하고 불러오는 기능까지
완료됐다고 해석하면 안 된다. 기존 EVS1 저장 영역과 진화 이력 바이트를 재사용하지 않는다.

## 검증

```powershell
.venv\Scripts\python.exe -B -X utf8 true_patches\mega_evolve\verify.py
.venv\Scripts\python.exe -B -X utf8 true_patches\mega_evolve\verify_phase1.py
```

두 번째 검증은 실제 GCC/ARM 런타임, 설치된 훅, 원래 날씨 선택·날씨 변경 기술의
카운터 처리, 방어 계산 소비자를 실행한다. 특성 활성/억제 판정, 기존 종족값 함수,
정수 나눗셈, UI·로그·색상 애니메이션 서비스는 fixture로 공급한다.
단계 상한/배율/초기화, 천진/단순/저하 방지, 날씨 배율·복합 타입, 강한 날씨 교체,
일반 날씨 차단, 발생원 억제/이탈, 메시지 ID와 한국어 exact-match 계획,
잘못된 상태 입력, 설치 명령·동굴 해시 변경 거부를 확인한다.

검증은 기존 영문 풀스택을 메모리에 읽어 적용하며 NDS·세이브·state 파일을 만들지 않는다.
영문/한글 풀스택 롬 빌드와 에뮬레이터 화면 검수는 별도 요청 시 진행한다.
기존 함수·구조 기준은 [pmdsky-debug](https://github.com/UsernameFodder/pmdsky-debug)이며,
Alpha 및 현재 풀스택의 실제 명령과 대조했다.
