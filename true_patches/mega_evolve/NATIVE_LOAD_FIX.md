# 실제 로더와 저장 업데이트 연결 수정

## 확인된 원인

Alpha ARM9의 MD 로더02052358은 문자열 리터럴을 통해
`rom0:/UTILITY/monster.md`를 읽는다. 기존 메가 데이터 설치는
`BALANCE/monster.md`만2273행으로 확장했고 UTILITY는1155행이었다.
새 ID로 실제 게임에서 조회하면 표 밖 메모리를 읽는다.
기존 검증은 BALANCE 파일을 직접 RAM에 넣어 이 결함을 놓쳤다.
기술 로더도 UTILITY를 읽으므로 추가 진화체의 기술 목록 연결 역시 누락됐다.

`mega_evolve_native_data`는 메가 적용의 마지막에 완성된 MD와 waza_p를
실제 UTILITY 경로에 연결한다. 기존 Alpha 입력의 양쪽 원본은 동일하다.
양쪽 파일 일치, 파일 해시, 실제 MD 경로 리터럴을 공개 verify에서 검사한다.

## 기존 업데이트 흐름

일반 저장을 정상 디코딩한 후에만 resident 상태에 메가 저장 형식의
미갱신 여부를 기록한다. 구형11비트는 pending, ME12는 schema1이다.
잘못된 ME12 버전은 여전히 디코딩 전에 거부한다.

기존 unionall 공통68의 ProcessSpecial77 판정과76 갱신 완료를 확장한다.
Alpha 업데이트 플래그가 이미 완료됐어도 메가 형식이 pending이면
같은 기존 업데이트 흐름을 실행한다. 완료 시 RAM schema1로 전환하며
기존 Alpha 플래그·업데이트 스크립트·도핑 가져오기 선택은 유지한다.
양쪽 process 은행의76/77에 독립 코드를 추가하여 공유 효과를 바꾸지 않는다.

RAM의 포켓몬 ID는11비트 파일을 읽은 직후부터 정상16비트 값이다.
기존 종을 자동 메가로 바꾸거나 도핑·기술·별명을 초기화하지 않는다.
실제 저장 파일의 ME12 기록은 기존 정상 저장 경로가 맡으며,
업데이트 완료와 파일 저장을 혼동하여 손상된 파일에 표식만 쓰지 않는다.

## 검증

`verify_native_integration`은 실제 ARM9 MD 로더가 요청한 경로를 사용해
1118개 추가 항목의 도감번호·이미지 번호·원본 이미지 버퍼 크기·유효성 판정을 검사한다.
기존 Alpha 버전0/255와 메가 pending0/1 조합의 실제 ARM 업데이트
코드를 실행한다. 공통 실행 버퍼를 바꿀 때는 실제 Alpha와 같이
명령 캐시를 무효화한다.

사용자가 다시 첨부한131072바이트 Complete.sav의 양쪽 일반 슬롯을
실제 체크섬/로드/종 codec으로 읽고 루카리오490·부스터736을 확인한다.
업데이트 판정·완료는 포켓몬 레코드를 변경하지 않는다. RAM에서12비트
기록/재로드 시 전체559종 ID와 추가 메가·이로치 ID도 보존한다.
세이브 파일은 읽기 전용이며 해시를 비교한다.

flash I/O, 파일 읽기와 ProcessSpecial 복귀는 모델이다. 실제 MD 조회,
체크섬·종 codec과 업데이트 효과 코드는 실행한다. DraStic에서 진화 화면과
교차로→던전 전환이 실제로 정상화됐다는 실기 검증은 별도로 필요하다.
이전의 다른262144바이트 Completee.sav는 재현 근거에서 제외한다.
