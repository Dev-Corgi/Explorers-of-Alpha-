# 던전 캐릭터 갱신 캐시 경로 수정

마을 메가 이미지 정상화 이후, 메가가 포함된 던전 파티의 이미지 깨짐이
사용자에게 재현됐다. `022FBB1C`의 캐릭터 갱신 루프는20개 개체를 돌며
`022FBB6C`에서 아직 기존1155칸 캐시를 apparent 종 ID로 직접 읽었다.
기존 phase5는 cache getter와 이미지 로드의 조회만 연결하여 이 경로를 놓쳤다.

새 `ME_SpriteActorCacheReadHook`은 같은 공통 확장 캐시를 읽고,
이미지 연결 번호를 entity+0xA8에 저장하는 native 경로로 반환한다.
다음 그리기 함수의 r0(entity+0x2C)와 다른 live 인자를 유지한다.
영구/apparent 종과 실제 상태이상 바이트를 바꾸지 않는다.

`verify_actor_sprite_cache`는 실제 ARM9/ov29/ov36과 heap bootstrap의
체크섬·재배치 경로를 실행한다. 일반 루카리오490와 메가 해피너스1625,
메가 루카리오2065를 섞어 조회한다. 기존 배열의 새 ID 위치에 고의로
잘못된 값을 넣어 이전 경로가 틀린 값을 읽는 실패를 먼저 재현했다.
수정 후에는 각 개체의 올바른 캐시 슬롯과 r0 인자, 실제 위액 상태를
보존하는지 검증한다. 파일 I/O는 모델이다.
실제 native 개체 초기화022FDDC0도 실행하며 일반/메가 모두 위액 바이트가
0으로 초기화됨을 확인한다. 따라서 이후 어느 시점에 상태가 설정되는지
실행 상태를 추가로 확인해야 한다.

위액이 의도치 않게 남는 문제와 교차로의 던전 진입 실패는 별도 조사 중이다.
원본 Alpha ExtraSpace에 특정 던전(ID19/53/77/78/79/80 등)의 팀 위액을
설정하는 코드가 있지만 기본 해안 동굴 ID1은 그 조건에 포함되지 않는다.
이를 이유로 전체 위액 상태를 지우거나 기존 던전 규칙을 삭제하지 않는다.
해당 실행의 실제 던전 ID·monster+0xD8와 캐시/개체 메모리를 확인해야 한다.
휴대폰의 Complete.sav와 상태 파일은 원본을 변경하지 않고 읽기만 한다.

2026-10-14: manifest version12로 영문·한글 재빌드 및 모듈 검증을 통과했다.
수정된 실제 ROM으로 위 캐릭터 갱신·초기화 회귀 검증도 통과했다.
휴대폰 ADB는 잠시 연결됐으나 복사 전에 끊겨 실행 상태 파일은 확보하지 못했다.
위액·교차로 문제의 해결 완료나 DraStic 실기 통과를 주장하지 않는다.
