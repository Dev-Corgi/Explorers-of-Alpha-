# 페이즈 6 — 진화의 샘 연결

기존 **진화** 메뉴 하나로 단계가 이어진다. 별도 메가 진화·이로치 메가 진화
메뉴는 추가하지 않는다. 원래의 요약·취소·일반 퇴화·지원 폼 변경은 유지한다.

| 현재 단계 | 진화 결과 | 조건 |
|---|---|---|
| 기존 일반 진화 전 | 기존 진화체 | 기존 조건 |
| 노고치·노라키 | 노고고치·신비록 | 레벨20 |
| 최종 진화형 | 메가 | 레벨80 이상 |
| 메가 | 이로치 메가 | 추가 레벨·도구 조건 없음 |
| 이로치 메가 | 추가 진화 없음 | 퇴화 가능 |

메가 분기가 여러 개면 기존 진화 대상 선택 화면에서 Mega X/Y/Z 등 분기를
선택한다. 메가 상태에서 다른 메가 분기로 바로 바꾸는 메뉴는 제공하지 않는다.
다른 분기로 가려면 최종 진화형으로 퇴화한 뒤 다시 진화하여 선택한다.
포켓몬 자체 이름에는 메가·이로치 접미사를 붙이지 않는다.

퇴화는 이로치 메가→해당 분기의 메가→최종 진화형 순서다. 메가/이로치의
진화·퇴화는 경험치·레벨·도핑·별명·성별 및 기존 진화 이력2바이트를 보존한다.
일반 진화는 기존 이력 처리와 껍질몬 생성 경로를 유지한다. 진화 판정과 저장
능력치 계산은 분리되어 반복 진화로 도핑·영구 보너스가 누적되지 않는다.

기존 원시회귀555/556, 오리진552/551/536은 샘에서 이미 메가 단계로 판정하고
바로 대응 이로치 메가로 진화한다. 원점별 기존 ID를 합치거나 스토리 개체를
일괄 변경하지 않는다. 호환 메가 ID1917/1923/2179/2185/2193을 별도의 추가
메가 진화 대상으로 노출하지 않으며, 이로치에서 퇴화한 뒤 다시 각성하는
경로는 이 호환 메가 ID에도 연결한다. 오리진의 기존 무료 폼 변경 경로는
메가의 레벨80 조건을 우회할 수 없게 제외한다.

## 구현과 배치

- `phase6.json`:1118개 명시적 경로와12개 EN/KO 확인·결과·분기 문자열.
- `phase6_spring.c/S`: 기존 luminous_evolution의 샘 동작을 기반으로 한
  mega_evolve 소유의 독립 샘 컨트롤러. 기존 진화 동작(action3)을 사용한다.
- `mega_evolve_phase6.py`: 기존 샘 훅과 공통 메시지 호출을 확인하고 새 샘
  컨트롤러에 연결한다. 이전 모듈의 샘 실행 몸체와 스토리 스크립트는 보존하고,
  native 호출 지점만 새 컨트롤러에 연결한다.
- ov16 뒤에 적용 시점에32KiB를 동적으로 할당한다. 코드·표·BSS가 할당
  범위에 들어가는지 검사하며 ov36 시작 주소를 침범하면 거부한다.
  실행 코드를 압축하지 않는다. 공통 heap runtime·보호 prefix·team_push는
  이번 샘 코드 배치로 변경하지 않는다.
- 샘 내부 상태/콜백만 ov16을 사용한다. ARM9의 팀 선택 필터는 기존과 같이
  샘의 선택 모드에서만 이 컨트롤러를 호출한다. 진입과 재선택 시 상태를
  초기화하여 취소 후 다른 개체/일반 진화에 이전 분기가 남지 않게 한다.
- 새 문자열은20626부터 빈 새 인덱스에 넣고 native ID는+1이다. 한글은
  기존 mega_evolve 문자열과 동일하게 호출자의 exact-match 번역 입력으로
  연결하며 korean은 마지막에 적용한다.

## 검증 범위

`verify_phase6`은 실제 ARM 샘 코드로 전체 경로의79/80/100레벨 판정,
메가의1레벨 이로치 진화, 성별·분기, 잘못된 대상 거부,1114개 형태의 퇴화,
퇴화 후 재진화, 전체 개체 기록 보존을 확인한다. 일반 레벨20 진화와
껍질몬 생성, 기존 지원 폼 변경, 첫 방문 제한도 함께 확인한다.

기존 진화 메뉴의 실제 native 선택→취소/확인→애니메이션 변환 호출을 실행한다.
별도 action12/13 메뉴는 없으며 진화는 기존 action3이다. 창·입력·재고·일부
스크립트 서비스는 모델이다. 스토리 스크립트는 수정하지 않는다.

공개 apply/verify 및 전체 이미지/MD/ov16/FAT/FNT 왕복은 메모리에서만 한다.
기기 RAM·실제 화면·전투 통합 검증은 페이즈8이고, 개별 강화 특성 효과는
페이즈7이다. NDS·세이브·풀스택 결과물을 새로 출력하지 않는다.
