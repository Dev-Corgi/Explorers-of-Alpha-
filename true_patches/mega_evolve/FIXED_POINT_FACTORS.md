# 적응력·필터의 고정소수점 상수 교정

실제 엔진의02001C80/02001DF4/02001CB0은 fx64_16을 사용한다.
메모리 순서는 upper32, lower32이며 소수부는16비트다. 일반적인 little-endian
uint64 Q16.48로 읽거나 쓰면 안 된다.

| 경로 | 이전 두 word | 올바른 두 word |
|---|---|---|
| balance_change 적응력1.7 | 33333333,0001B333 | 00000000,0001B333 |
| mega_evolve 필터·하드록0.8 | CCCCCCCD,0000CCCC | 00000000,0000CCCC |

이전 적응력 상수와 입력100을 실제 ARM Multiply로 계산하면 중간값은
4,293,656,745.999695다. 최종 게임 피해량이 이 숫자라는 뜻은 아니다.
교정 후 같은 중간값은169.99969482421875이며 native 정수 변환은170이다.
일반 자속은150, 비자속은100이고, 두 적응력 ID24/99가 함께 있어도 한 번만
곱한다. 적응력Ⅱ의 별도 효과 활성화는 기존 페이즈7 범위를 유지한다.

이전 테스트는 잘못 가정한 Q16.48 곱셈 모델로 같은 오류를 상쇄해 놓쳤다.
해당 세 테스트의 곱셈 모델을 제거하고 실제 엔진 곱셈/정수 변환으로 바꿨다.
`verify_native_factors`는 완성 ROM에서50개 입력·타입·특성 조합을 실행하고,
이전 상수를 다시 주입하는 음성 대조군으로 오류가 재현되는지도 검사한다.
영문·한글의 관련 실행 코드와 runtime 파일도 대조한다. 결과 해시는
`data/phase3_fixed_factors_validation.json`에 남긴다.

특성 가용 여부, 전용 아이템의 자속 추가 효과, 파일 IO는 테스트에서 제어한다.
실제 STAB 타입 판정·조회 래퍼·필터 상수 선택·고정소수점 곱셈·정수 변환은
ARM 코드로 실행한다. 전체 전투나 기기 FPS 검증을 주장하지 않는다.
