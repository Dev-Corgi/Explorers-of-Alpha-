# bug_fixes

기준 Alpha 롬의 버그를 수정하는 모듈이다. 풀스택의 게임플레이 모듈 뒤에
적용하며, 한글 모듈은 그 이후에 적용한다. v2부터 보조 코드의 overlay36
동굴은 적용 시점에 동적으로 할당한다. 기존 모듈 업그레이드는 기준 롬부터
풀스택을 재구성하는 방식으로 적용한다.

## v5: Alpha 스토리 스탯 상한 제거

Alpha의 아군 초기화 처리 `0x023AA0D8`에서 스탯캡 블록을 건너뛰고
기존 후속 난이도 처리 `0x023AA1E0`로 이동한다. 기존 명령어를 확인한 뒤
분기 한 개만 바꾸며 추가 동굴이나 문자열을 사용하지 않는다.

원본 코드는 난이도 3(Expert)에 30을 더하고, 난이도 4(Hardcore)는
그대로 시작한다. 디아루가 전에는 90, 디아루가 후에는 150을 더하며,
다크라이 이후에는 제한하지 않는다. 공격·특공·방어·특방은 그 값으로,
최대 HP는 그 값 +50으로 제한한다. 따라서 실제 코드의 상한은 다음과 같다.

| 진행 | Expert 스탯 / HP | Hardcore 스탯 / HP |
| --- | --- | --- |
| 디아루가 전 | 120 / 170 | 90 / 140 |
| 디아루가 후·다크라이 전 | 180 / 230 | 150 / 200 |
| 다크라이 후 | 스토리 상한 없음 | 스토리 상한 없음 |

아군 4칸을 순회하며 엔티티가 유효한지 검사하고 종족 192/530/543은
제외한다. 이 처리는 던전의 네 스탯 바이트와 실제 최대 HP를 수정한다.
Alpha+에서 네 바이트는 도핑 V이므로 이 제한을 유지할 이유가 없다.
Drink의 레벨별 도핑 배분 제한과 다른 난이도 기능은 그대로 유지한다.
이미 사라진 도핑을 복구하는 기능은 아니며, 사과의 숲 종료 시 도핑이
0으로 바뀐 현상의 원인이 이 블록이라고 확정하지 않는다.

`verify_stat_caps.py`는 실제 난이도 판독과 제한 루프를 실행한다.
네 난이도 × 세 스토리 구간 × 다섯 종족 배치 × 16개 스탯 값의 960개
경우에서 원본 상한을 재현하고 수정 후 모든 슬롯의 도핑·HP 보존을
확인한다. 낮은 도핑 V와 높은 CalcStat HP, 상한 경계 및 제외 종족도
포함한다. 뒤따르는 난이도 설정의 실제 메모리 쓰기도 동일한지 확인한다.
전체 `verify.py`에서 동굴 재배치 검증과 함께 실행한다.

## v4: 메타몽·조로아크 계열의 스폰 변신 복구

Alpha 스폰 보조 함수의 `0x023BF4A8`은 일반 층의 Imposter/Illusion도
즉시 종료시켜, 바로 뒤의 변신 대상 선택 코드가 실행되지 않았다. 일반 층은
기존 대상 선택·외형 변경·변신 상태 설정으로 진행하게 고친다. Illusion의
능력치 단계 보정과 Imposter의 타입·특성·능력치·기술 설정도 원래 코드를 따른다.

고정된 전체 층에서는 Alpha의 기존 동작을 유지한다. 변신 후보 목록이 비었으면
난수 선택 전에 안전하게 종료하며, 자기 종밖에 없는 목록도 변신하지 않는다.
새 스폰 함수를 만들거나 종별 특성을 변경하지 않는다.

`verify_spawn_transform.py`는 실제 ARM 스폰 보조 함수를 실행해 외형·상태,
Illusion 보정, Imposter 타입/특성/능력치/기술 설정, 빈 목록·동일 종,
기존 고정 층 동작을 확인한다. 전체 `verify.py`에서 함께 실행한다.

## v3: 던전 층수를 Hardcore 기준으로 통일

`UTILITY/inter_d.bin`에서 `PERFORMANCE_PROGRESS_LIST`의 45(기계배열 소지),
56(Vanilla), 57(Difficult) 플래그로 활성화되는 단축 종료 조건을 제거한다.
33개 던전 ID의 62개 조건이 대상이며, Expert와 Hardcore도 기계배열에 의한
단축 없이 동일한 전체 층수를 사용한다. 예를 들어 뇌운산은 모든 난이도에서
기계배열 소지 여부와 관계없이 40층까지 진행하고, 33층 의뢰에 도달할 수 있다.

무조건 종료, 스토리 및 다른 아이템 플래그에 따른 종료 조건은 원래 바이트를
보존한다. 기계배열의 전투 효과와 가방 용량 감소, 난이도의 다른 효과는 유지한다.
문자열을 추가하거나 바꾸지 않는다. 기존 동굴과 ARM 수정 이후 같은 모듈에서
데이터 수정을 적용하고, 모듈 적용 검증에서도 단축 종료 조건의 제거를 확인한다.

`verify_floor_limits.py`는 원래 20/22/30층 종료를 재현한 뒤 실제 계단 종료
ARM 루틴에 수정한 종료 테이블을 제공한다. 대상 던전의 기존 종료 경계와
최종 층을 네 난이도 × 기계배열 유무 조합으로 확인한다. 전체 `verify.py`에도
통합되어 있으며, 기존 배포 롬은 읽기만 하고 결과는 임시 파일에 만든다.

## v2: Mirror Armor, Trace, Neutralizing Gas

- **Mirror Armor:** 저장해 둔 원래 엔티티 포인터로 능력치 하락의 출발점과
  대상을 뒤집는다. 특성 메시지는 Mirror Armor 소유자에게 표시하고,
  Defiant·Competitive가 사용하는 대상도 실제 반사 대상에 맞춘다.
- **Trace:** 원래 특성 슬롯을 선택하기 전에 `AbilityIsActive`를 호출한다.
  위액, 인접 Neutralizing Gas 및 특성 억제 도구가 반영된다. Trace가
  없거나 억제됐을 때도 기존 Color Change 처리로 계속 진행한다.
- **Neutralizing Gas:** 층 전체 플래그 대신 인접 8칸의 살아 있는 소유자를
  매번 검사한다. 적·아군 모두 영향을 받으며 이동·기절·억제가 즉시 반영된다.
  소유자는 스스로를 억제하지 않고, 가스 특성끼리 서로 억제하지 않는다.
  위액과 특성 억제 도구는 가스 자체를 끌 수 있다.

## v1: 싸라기눈의 일반 자연회복 가속 제거

`TickStatusAndHealthRegen`의 `0x023111F0` 명령은 Ice Body가 없는 개체도
싸라기눈에서 회복 분모에 -100을 적용한다. 이 명령만 NOP으로 바꾼다.
Ice Body의 Alpha 접촉 동상 효과, Quick Healer, Rain Dish, Dry Skin 및
나머지 회복 보정은 건드리지 않는다. 이 수정 자체는 동굴을 사용하지 않으며,
v2의 특성 수정에도 추가 문자열은 없다.

HP 787, 기본 회복 분모 200, Quick Healer가 있는 Kabutops라면 싸라기눈에서
평균 회복량이 회복 처리 1회당 39.35 HP에서 7.87 HP로 줄어든다.
이는 자연회복 부분만의 값이며, 날씨 피해 등 다른 효과는 별도로 처리된다.

검증:

```powershell
.venv\Scripts\python.exe -B true_patches\bug_fixes\verify.py
```

검증은 임시 파일에 모듈만 적용하고 실제 ARM 회복·특성·능력치 하락
루틴을 부분 실행한다. 회복·날씨·아이템 조건과 메시지·애니메이션·타일 조회
등의 보조 서비스는 검사 환경에 맞춰 제공한다. Mirror Armor의 실제 스탯 하락과 Defiant·Competitive 반응,
Trace의 두 슬롯 및 Color Change, 가스의 거리·진영·이동·기절·억제를 확인한다.
풀스택 롬을 다시 빌드하거나 배포 결과물을 수정하지 않는다.
