# status_adjust

## v27: 처치 시 멸망의 노래 해제

기존 멸망의 노래 해제 조건과 카운트다운은 그대로 유지하고 아래 조건만 추가한다.

멸망의 노래 상태인 포켓몬이 다른 포켓몬을 실제로 쓰러뜨리면 자신의
멸망의 노래 카운터만 0으로 지운다. 아군·적군 모두 적용하며 다른 상태이상은
그대로 유지한다. 게임이 기절 원인으로 전달한 포켓몬을 처치자로 사용한다.
상태 아이콘을 갱신하고 기존 멸망의 노래 해제 메시지를 출력한다.
기존 메시지 ID `0xC83`(`text_e.str` 인덱스 `0xC82`)를 재사용하므로
새 문자열이나 한글 번역 항목은 추가하지 않는다.

자기 자신의 기절, 처치자 없는 기절, 몬스터가 아닌 처치자, 이미 쓰러진 처치자,
동료 돌려보내기(`WENT_AWAY = 604`)는 해제 조건에서 제외한다.
부활로 기절을 피한 경우에는 원래 게임의 `HandleFaint`에 도달하지 않는다.

US ov29 `HandleFaint`의 `0x022F7F38`을 후킹한다. `z_move_v2`의 함수 진입 훅과
`balance_change`의 스택 프레임 훅 다음이며, `control_mode_enhance`가 동료의
다음 층 부활을 예약하고 조기 반환하기 전이다. 기존 적용 순서는 유지한다.
실행 코드는 동적 배정하는 ov36 동굴에 들어가며, v27부터 512바이트를 예약한다.

## 검증

저장소 루트에서 실행한다. Unicorn이 필요하다. 기존 로컬 테스트 의존성
디렉터리 `tools/.korean_jit_test_deps`도 검색한다.

```powershell
.venv\Scripts\python.exe true_patches\status_adjust\test_perish_song.py
```

기준 ROM을 읽어 메모리에서 모듈을 적용하고 조립된 ARM 코드를 실행한다.
카운터 해제, 다른 상태 보존, 메시지·아이콘 갱신, 제외 조건, 반복 처치,
레지스터·플래그·스택 보존, 기존 훅 적용과 모듈 간 훅 충돌을 검증한다.
ROM 파일 저장이나 풀스택 빌드는 하지 않는다.
